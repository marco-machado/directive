# Neon Directive

**Neon Directive** is a real-time squad tactics game about controlling engagements in a hostile corporate city.

Every contract can be finished unseen, fought through, or anything in between. Players use positioning, sightlines, coordinated attacks, and tactical withdrawal to decide when an engagement starts, how it unfolds, and how to recover when it goes wrong.

**Core promise:** Choose when the fight starts, how it unfolds, and when to disappear.

It is built with React Three Fiber and served by one Cloudflare Worker. Campaign progress lives in a per-player Durable Object, addressed by a shareable save code.

It renders with three.js's `WebGPURenderer`: on WebGPU where the browser offers an adapter, otherwise on the renderer's WebGL 2 backend, so it needs a browser with WebGPU or WebGL 2 and hardware acceleration. Add `?renderer=webgl` to the URL to force the WebGL 2 backend.

## Design

Use these terms in docs, UI copy and design notes.

- **Genre:** Real-time squad tactics, not squad-stealth or squad-combat.
- **Design pillar:** Engagement control. Players decide when an engagement starts, how it unfolds, and how it ends.
- **Core system:** Detection and the alarm. Sightlines, detection meters, and the alarm decide whether an engagement stays quiet or goes loud, and the stand-down is how a loud one ends.
- **Engagement:** Any encounter with hostile forces, from first contact (a sighting, a takedown, or a shot) until the squad is out of sight again.
- **Player fantasy:** Outsmart and outmaneuver hostile forces, whether unseen, under fire, or slipping back out of sight.

## Run

Node.js 24 or newer. Install the locked dependencies with `npm ci`, then run `npm run dev`; the Cloudflare Vite plugin runs the Worker and Durable Object locally in workerd. `npm run build` bundles `dist/`; `npm run typecheck` runs the TypeScript compiler. `npm test` exercises district generation, navigation, detection and the alarm, abilities, every contract type, move orders (formation, single-file queues, appended waypoints and waits), revive, fog of war (including last-seen markers and patrol intel), the district's night dressing (street props stay off the navigation grid and the barriers, and a building's dressing stays inside the box the fade test uses), first-time tip milestones, contract 01's quiet route at several start times, each gear loadout's effect, each badge earned and missed, each Countermeasures level's effect and unlock, the campaign ledger (offers, recruits, upgrades, loadouts, migration that keeps a mission in flight), the client holding a fast win's payout claim until the server's minimum mission time, telling a camera drag or a long press from a click, the camera's framing math, and the tactical balance bot (it clears contract 01 unseen and knows only hostiles the squad has seen).

`npm run test:release` is the release check, run before a release (CI does not run it). It builds, serves the bundle with `vite preview` and the source with the dev server (each on the first free port from 4173 and 5173), and drives them in headless Chromium on the machine's GPU with real mouse, keyboard and touch input. The smoke (`tests/release/smoke.spec.ts`, on the build) runs twice, once on the backend the game picks (WebGPU where headless Chromium offers an adapter) and once with `?renderer=webgl` (project `smoke-webgl`), and checks the canvas runs on the expected one. It covers five viewports: 1440×900, 1280×720, 1180×820 and 744×1133 with touch go from the title through the contract board, deploy, a move order, pause, the mission menu with its Audio and manual dialogs, and a restart, plus a long-press waypoint on touch; a 390×844 phone must show the too-small notice. The playthrough (`tests/release/playthrough.spec.ts`, on the dev server, which it needs to read the page's modules and aim clicks at world points) loses an assassination (going loud lets the target escape; it starts new campaigns until a board offers one), retries and wins contract 01, buys an upgrade, drops the Worker to check the offline warning and the resync, and deploys the next contract. A test fails on any console error or warning, uncaught page error, failed request or HTTP error (except the requests the offline step drops on purpose), and on clipped text or controls outside the viewport. Install the browser once with `npx playwright install chromium`. Screenshots, frame times, small touch targets and failure traces land in `test-results/`; open the report with `npx playwright show-report test-results/release-report`.

`npm run typecheck` checks the browser code and, with `worker/tsconfig.json`, the Worker. After editing `wrangler.jsonc`, run `npm run cf-typegen` to regenerate `worker/worker-configuration.d.ts`.

Direct dependency versions are pinned to the npm registry's stable `latest` releases resolved during this rewrite. `package-lock.json` locks the transitive dependency graph.

`@react-three/fiber` 9.8.2 is patched: `patches/@react-three+fiber+9.8.2.patch` swaps its store's deprecated `THREE.Clock` for a Clock-compatible class backed by `THREE.Timer`, and the `postinstall` script reapplies it with `patch-package` on every install. When upgrading R3F, regenerate or drop the patch.

## Structure

- `src/game/`: serializable campaign data, renderer-independent simulation, navigation and line-of-sight.
- `src/game/campaign.ts`: campaign rules (contract offers, tiers and payouts, prices, roster, mission ledger) shared by the browser and the Worker.
- `src/game/mapgen.ts`: builds a district (city blocks, cover, patrols, objectives) from a contract's seed.
- `src/game/simulation.ts`: stealth, alarm, combat, abilities, objectives, revive and fog of war.
- `src/game/classes.ts`: operative classes and their abilities.
- `src/scene/`: React Three Fiber scene, procedural city and agents, camera, visual effects (`combat.tsx` draws tracers, muzzle flashes, sparks, smoke, debris, blast rings and scorch marks from pooled instanced batches; hit flashes, stun rims and deaths swap unit materials), health bars, objective beacons, off-screen objective arrows and planned routes (`routes.tsx`: each operative's move order as a dashed line in its class color, with a numbered marker at every waypoint). Frame updates mutate Three.js objects; UI snapshots update at 10 Hz. The camera centers its view in the space the HUD leaves free (the `.view-frame` element), pans with middle-drag, orbits with right-drag and zooms with the wheel: missions open on a tactical view of the selection (about 22 m of street across that space, and never zoomed out so far that an operative is drawn under 24 px at any tilt, so tilting never changes the zoom) and follow the selection until the player pans, while the briefing and the title show the whole district. `framing.ts` holds that math, and `drag.ts` keeps a drag from counting as a click. A click that hits no unit picks the nearest one within 28 px before it counts as a street click.
- `src/scene/district.ts`, `textures.ts`, `materials.ts`, `lighting.tsx`, `bloom.tsx`: the district at night, all procedural. `district.ts` dresses a plan from the contract seed, on its own random streams so mapgen's layout never changes: building massing (podium and tower, stepped tiers, slabs), rooftop plant, antennas and name boards, vertical neon signs in a generated glyph script, awnings, and a street kit of sidewalks, curbs, crosswalks, corner lamps, vending kiosks, crates and puddles. Props that stand on the ground sit only where no unit can (beside a wall, or past the bounds); past the bounds a ring road with parked cars and low shops, dimmed and nearly gray so it reads as outside the district, fades into the dark, and a bright line on the tactical grid marks the edge. `textures.ts` draws one facade atlas per contract (wall panels, lit and dark windows, storefronts, roof grime) and the sign atlas on canvases; `materials.ts` builds the district's node materials with TSL (`three/tsl`): facade bays, per-instance roughness, wet puddle reflections, the fade, the out-of-zone grade and the capped highlights; `lighting.tsx` the moonlight, a camera-side fill and eight practical point lights; `bloom.tsx` a threshold bloom pass (three's `RenderPipeline` and `BloomNode`) on the emissive windows, neon and signs. `renderer.ts` picks the backend and creates the renderer.
- `src/net/campaignClient.ts`: creates or loads the player's save code and reports deploys, completed contracts, purchases, recruits and dismissals to the Worker.
- `src/app.ts`: the shared `Simulation`, campaign client and player connection.
- `src/main.tsx`: screen flow (title, mission select, headquarters, mission, debrief), hotkeys and dialogs.
- `src/ui/`: React DOM screens and HUD, event callouts, SVG icons and class portraits, and the Web Audio manager (`audio.ts`: positional cues, music and ambience loops, volume groups saved in `localStorage['ndAudio']`). The samples in `public/audio/` were generated with ElevenLabs sound effects; `artifacts/generate-audio.py` holds the prompts.
- `worker/`: Worker entry (`/api/*` routes, static assets) and the `PlayerCampaign` Durable Object.
- `scripts/balance.ts`: headless balance check. Two bots play 12 seeds of every contract type and tier with three rosters (the starters, four operatives, four fully upgraded):
  - the no-tactics bot (`scripts/bots.ts`) selects all, clicks the objective, then extraction; it revives the downed and uses no abilities;
  - the tactical bot (`scripts/tactical.ts`) routes around vision cones, waits out patrols and clears a blocker quietly (a sniper shot or a volley that kills, a takedown nobody sees, an EMP), and goes loud only when the alarm sounds or after 45 s without progress. It knows only what the squad has seen and acts only through the player's orders.

  It prints win rate, quiet wins, alarm rate, median time and HP lost per contract type and tier, then each roster's mean win rate and whether the balance targets hold. Run `node --experimental-transform-types scripts/balance.ts`; `--bot`, `--seeds`, `--roster`, `--tiers 1,3` and `--types heist,escort` narrow it, `--modifier lockdown` (or `nokill`, `unknown`, `carry`, `through` or `called`) plays every contract with that modifier where it fits, `--quiet-only` stops the tactical bot from going loud on its own, and `--loadout suppressed/light` plays every roster with that loadout. `--cm 0,1,2,3` instead plays the fully upgraded four at those Countermeasures levels at tier 5, and `--loadouts` plays it with all six loadouts at tiers 4 and 5 and prints each bot's wins and quiet wins, its best loadout for each, and whether its best one meets the targets. `scripts/balance-current.txt` holds all three outputs for the current rules, and `scripts/balance-baseline.txt` the output from before the difficulty pass.

## Play

The title screen continues the campaign, loads a save code from another device, or opens the operator manual. On the mission select screen, pick one of three contracts (each shows a threat read, from low to extreme, that weighs its tier against the roster's size and upgrades) and up to four operatives, then deploy; the briefing lists the objectives and the hostiles known to be in the district. Each contract is a generated district that grows with its tier: **assassination** (kill the target before it flees once the alarm sounds; intel marks a 6 m last known area around it, drawn as a TARGET AREA ring until the squad sees the target, then recentered on wherever the target was last seen, and a fleeing target's exit is flagged in red), **data heist** (hold the vault terminal for 12 s), **sabotage** (plant two charges) **escort** (stay beside the VIP for 5 s to free them, then bring them to extraction; under fire the VIP ducks behind cover near the nearest operative and takes half damage), from tier 2, **elimination** (down every hostile the district started with, cameras and turrets included; reinforcements don't count, and the tracker shows how many are left) or, also from tier 2, **intercept** (a courier and two escorts walk a fixed route from one edge exit to another, at least 16 m and most of the district's width apart, setting off 6 s after the squad deploys; the briefing rings the courier's entry as a COURIER AREA, watching the courier stand at a street corner it walked to draws its whole route like a patrol's, the alarm sends it running for its own exit at once, and the contract fails if it gets there; every district guarantees the squad can reach some corner of the route 5 s before the courier) or, from tier 3, **smash and grab** (three caches at least 8 m apart, each held by a posted guard; an operative standing at one opens it in 3 s. Opening the first starts a lockdown clock, alarm or not, of 30 s plus 5 s a tier, which the tracker counts down, and opens extraction; the contract fails with the squad still inside when it runs out. The other caches turn optional, and each one opened pays 200 bonus credits, reported with the win) or, also from tier 3, **surveillance** (three unarmed executives walk their own beats, starting at least 8 m apart; an operative tags one by keeping it, unaware, in sight within 8 m for 3 s, and Recon's mark tags it at once. Each executive's ring fills as it is watched and follows it while in sight. The alarm sends the untagged ones running for exits, as an assassination target does; one that gets away or is killed is lost, the squad never fires on one unordered, and the contract fails once fewer than two can still be tagged. Two tags open extraction; the third turns optional, and tagging all three earns intel on the next contract). Every contract ends when the whole squad reaches extraction.

Guards patrol with vision cones, cameras sweep, and from tier 4 turrets guard objectives. Hostiles grow 5% tougher and 4% deadlier per tier up to tier 3, then a further 10% and 15% per tier. A cone shows exactly the ground its hostile can see: it stops at the first building in the way. Posted guards (two at each objective, never with their back to the map edge, where a takedown would have nowhere to end) turn 60° to one side every 6 to 8 s, alternating sides, and hold that look for 2 s; the schedule follows the contract seed. Enemies outside your squad's line of sight (10 m, not through buildings) are hidden. A hostile that drops out of sight leaves a fading marker at its last known position and heading for 12 s, labeled with the seconds since; it clears when the hostile is seen again. Once the squad watches a guard reach the end of a patrol leg, that guard's whole route stays on the ground as a dashed line for the rest of the mission. A full detection meter, or a hostile that survives being hit (unless suppressed rifles hit it: then it only grows suspicious, until that fills its meter), raises the alarm: nearby guards hunt the squad's last known position, the first reinforcements arrive 5 s later at the exit nearest extraction, between the squad and its way out, then more every 20 s, and an assassination target runs for an exit. Alarmed hostiles fire in every direction and the squad fires at will, so to stand the alarm down the squad has to stay out of every hostile's sight and firing range, with no shots fired, for 25 s (cameras keep watching; an EMP blinds them). Hostiles then return to their patrols, reinforcements stop, and the squad holds fire again; a fleeing target keeps running. The first alarm brings up to 8 reinforcements. Each later alarm in the same mission brings 4 more (plus any an earlier alarm never sent), its first wave again 5 s after it at the exit nearest extraction, one more heavy leading each of its waves than the alarm before (until whole waves are heavies), and it takes 10 s longer to stand down; after a stand-down the status bar and the mission tracker say what the next alarm brings. Before the alarm the squad only fires at ordered targets, and operatives ordered onto the same target hold fire until every one of them can hit, then fire on the same frame; a volley that kills stays quiet. An attack order on an unaware guard, heavy or target (no alarm, not suspicious) that the selection's volley would not kill is a takedown instead: the nearest selected operative circles out of the hostile's vision cone to within 1.2 m and finishes it after 1.5 s. A heavy needs two operatives. A takedown is silent unless another hostile sees it. Hovering a hostile shows what the order would do, for example `Takedown · ROOK` or `48 / 75 · will alert`. Finishing without ever raising the alarm pays a 25% stealth bonus; a stood-down alarm still voids it. The after-action report names what raised the first alarm (the hostile, the operative it caught, the nearest objective and the mission time) and pins it on a district map. The comms log keeps the last six reports, leaves out routine move, waypoint, wait and hold confirmations (screen readers still hear them), and collapses a repeated report into one line with a count. Low barriers halve fire from the far side for an operative within 1.1 m of one. A shield over the operative and on its squad card shows it is in cover against every armed hostile that threatens it (during the alarm, those with it in range and in sight; before it, every one the squad can see); the shield turns red when one of them has a clear shot. With a known armed hostile about (in sight, or a last-seen marker), a move order within 1 m of a barrier ends on the barrier's side away from the nearest one, the squad lining up along it, packed closer if needed to stay within the stretch it shelters; a shield on a marker under the pointer previews that spot.

Operatives come in four classes, each with one ability: Assault (breach grenade, loud), Support (field heal), Recon (silent sniper shot that marks nearby enemies through walls) and Tech (EMP that stuns guards and turrets and blinds cameras). A downed operative can be revived by a teammate during the mission.

Select agents with click or 1–4, Shift-click (or long-press) to combine, A to select all. Shift+1–4 uses that operative's ability; targeted abilities wait for a click and Esc cancels. Click the street to move, a hostile to take it down or fire a volley, or a downed teammate to revive them. A click past the district's edge (the bright line, beyond which the city is dimmed) acts on the nearest point inside it, and a line from the pointer shows where. A click on the street replaces each selected operative's route; Shift+click (a long press on touch) adds a waypoint to it instead, up to 8 per operative, the squad lining up from where its routes end. W adds 2 s of waiting at the last waypoint (up to 10 s, then clears it), so two operatives can time a crossing past a patrol; an operative without a route waits where it stands. Routes show as dashed lines in each operative's class color with numbered waypoints (and their waits), for the selection and, while paused, for the whole squad. S holds position and drops the route. Space pauses; orders still work while paused, so a route can be planned leg by leg before resuming. Middle-drag to pan, scroll to zoom, right-drag to rotate and tilt the view; the left button only selects and gives orders. During a mission the view follows the selection (the whole squad when nothing is selected); after a pan it waits until the selection starts moving again, F, or a switch with R. F (or a double-click or double-tap on a squad card) glides the view to the selection; R switches to the whole-district overview and back to the view you left (its zoom, angle and pan). Directive runs on tablets and computers with a viewport of at least 744 × 600; phones are not supported. Touch uses tap commands, a long press for Shift+click (waypoints and multi-selection), one-finger drag to rotate, two-finger pan/zoom and the ability buttons on the squad cards. Arrows at the edge of the view point to objectives off screen, including the target's last known area and a fleeing target's exit. The mission menu (☰) pauses and offers restart, the manual, audio, auto-pause, tips and graphics quality (Low drops the bloom pass for slower devices; auto-pause and quality are saved in `localStorage['ndOptions']`); First-time tips dock under the mission tracker, one at a time (the newest waiting), the first time the squad sees a hostile, a hostile turns suspicious, the alarm sounds, an ability is ready, an operative goes down, and extraction opens. Each stays until dismissed and then never shows again on that device; the menu turns tips off and the manual's Reset tips shows them all again (both saved in `localStorage['ndTips']`). the speaker button opens the Audio dialog (mute, and master, music, ambience, effects and interface volume).

The campaign starts with VEX (Assault) and ROOK (Support). Until the first contract is completed, one recruit on offer is always a Recon or a Tech. Payouts run from 500 credits at tier 1 to 1,500 at tier 5, and the offered tiers rise with clearance: each completed contract earns 2 clearance points and each badge 1, and the base tier rises every 4 points. A won contract can earn five badges: Ghost (the alarm never sounded), Untouched (no operative went down, even if revived), Swift (extracted within the contract's par time, shown on the board: 18 s for an assassination, 28 s for a heist or an escort and 32 s for sabotage at tier 1, plus 12 s a tier), Bloodless (no hostile killed but an assassination target; on surveillance, no one at all) and Purge (every hostile the district started with is down; reinforcements don't count). Elimination offers neither Bloodless nor Purge, and its par time is 45 s at tier 1; on an intercept, Bloodless spares only the courier, and par is 20 s; smash and grab and surveillance have a 30 s par. The briefing lists them, the after-action report shows which were earned and why the others were missed, and headquarters keeps a service record. Until two contracts are completed, the board offers only tiers 1 and 2, whatever badges were earned. Once every upgrade is maxed, Countermeasures open: an opt-in ladder picked on the briefing. Level I makes hostiles notice the squad 25% faster, II also adds 15 s to every stand-down, and III also lifts the reinforcement cap. Winning the highest open level with at least one badge opens the next; the ladder pays no extra credits. The tracker shows the level as a CM chip. Until the first contract is completed, the first offer is always contract 01: the same hand-checked tier 1 data heist (seed `FIRST_CONTRACT` in `src/game/campaign.ts`) with a single patrol, where a squad that walks straight to the terminal and back stays unseen if it reads the patrol. The board is dealt at each deployment from the clearance (and once more on the first payout, to replace contract 01), so a newly unlocked tier appears on the board dealt at the next deployment; the after-action report and the contract board show the current clearance tier and how many more clearance points unlock the next one. From tier 2, after the opening, each offer has a one-in-three chance to carry a contract modifier that fits its type and is open at its tier, which adds 20% to its fee; the board card and the tracker show it as a chip, and the briefing explains it: **Lockdown** seals the exits 45 s after the first alarm, whether or not it stands down, and the contract fails if the squad is still inside (the tracker counts down); under a **no-kill clause** (not on elimination) each kill but a target cuts the fee by 15%, down to 25% of it, before the stealth bonus. The client reports those kills with the win. From tier 3 an assassination can carry an **unknown target**: the target holds a post and passes as a guard (SECURITY, with a guard's sight cone and health reading) until an operative watches it, unaware, from 5 m or closer for 2 s, or Recon's mark lands on it. The target area marks where it was last reported, and the briefing lists the target as unidentified. Killing the wrong guard is a guard kill (it costs Bloodless and counts against a no-kill clause), and on alarm the target hesitates as usual, then gives itself away by running. A heist can carry a **carry** clause: the vault gives up a package instead of data, to the operative at the terminal. Its carrier walks at 75% speed, can't fire, join an attack or use its ability, and drops the package where it goes down; any operative picks a dropped package up by standing on it (it gets a beacon and an edge arrow). To hand it over, send one operative on its own to stand beside the carrier: after 1.5 s with both standing still it takes the package (a squad move never swaps it). The squad card shows the carrier, and extraction needs the package in the zone. Two modifiers change how a contract ends (neither on contract 01, which keeps its out-and-back layout). On a **through-run** (not on intercepts) the squad starts at one corner and extracts at the opposite one: hostiles keep clear of the start, objectives sit away from both corners, reinforcement exits keep clear of both, and the first wave still enters nearest extraction, now ahead of the squad. Under a **called extraction** there is no fixed zone: once the objectives are done, a Call pickup button appears above the squad cards; click or tap an open street to call it there, and it lands 10 s later, its zone counting down. The whole squad must be in the zone once it has landed. Until the call, every reinforcement wave enters at a random edge exit; after it, every wave enters at the exit nearest the pickup. Modifiers are separate from Countermeasures, which the player picks. Contract types also unlock with clearance: each has an unlock tier (`UNLOCK_TIER` in `src/game/campaign.ts`; elimination deals from tier 2, the rest from tier 1), the board deals a type once the base tier reaches it, and the first board dealt after a type unlocks always includes it. The board and the after-action report name the next type to unlock and how many clearance points it takes, and the briefing explains a newly unlocked type once, as a dismissable tip. Offers and recruits reroll after every deployment, won or lost. Headquarters sells ammunition (300) and plating (250) for the whole squad, ability upgrades per class (200; −15% cooldown and +20% effect per level), each capped at three levels, and recruits (400; roster of up to six, duplicates allowed, dismiss to free a slot). How the gear levels are spent switches freely there: piercing rounds (+4 damage a level), suppressed rifles (a hostile that survives a rifle hit gains 100% − 20% a level of a full detection meter instead of raising the alarm) or extended barrels (+0.6 m of rifle range a level); heavy plating (+12 health a level) or a light weave (hostiles take 15% longer a level to notice an operative, though not the VIP). Level 0 is the same in every mode. Progress saves to a Durable Object keyed by a 12-character save code (shown as `XXXX-XXXX-XXXX` on the title screen, at headquarters, in the after-action report and in the operator manual). The browser generates its code and remembers it in `localStorage['ndPlayer']` before creating the player, so a retry after a lost reply reaches the same save; enter the code on the title screen or at headquarters on another device to continue there. The squad picked on the briefing is remembered for that save code in `localStorage['ndSquad']`, so a reload keeps it; operatives no longer on the roster are dropped from it. A pre-server `ndSave` browser save is imported on first visit, then removed; saves from before contracts existed are upgraded with their credits, upgrades and progress kept. The real-time mission runs in the browser. The Worker deals the contract offers, prices purchases and recruits, and pays the stored contract once per deploy, no sooner than 15 seconds after it. The client reports whether the alarm was raised, which badges it earned and, for a contract type that has them, its per-contract results; the Worker trusts that report for the stealth bonus, the badges and the rewards, after bounding the results by the contract. A contract type can pay rewards beyond credits from its results (`REWARDS` in `src/game/campaign.ts`): bonus credits for each optional objective past a free count, an operative who joins the roster (400 credits instead when the roster is full), or intel: the next deployment starts with every patrol route in its district drawn, and a restart of it keeps them. The briefing lists a contract's possible rewards and says when intel is waiting; the after-action report shows what was earned. Smash and grab pays its bonus credits this way, and Surveillance its intel; Jailbreak will pay its rewards too. If the Worker is unreachable, the game stays playable and warns that progress is not saved. After a failed save, the browser checks the Worker every 5 seconds; once it answers, its campaign replaces the progress that was not saved.

## API

| Route | Effect |
|---|---|
| `POST /api/players` | `{ code, legacy? }`: creates the player for a code the browser generated, importing the optional `legacy` Campaign; returns the existing player unchanged (`legacy` ignored) if the code is taken; 400 without a valid code |
| `GET /api/campaign/:code` | Current campaign |
| `POST /api/campaign/:code/missions` | `{ contractId, squad, countermeasures? }`: deploys an offered contract (or restarts the active one) at a Countermeasures level, 0 when left out, and deals a new board; returns `missionId` and the campaign; 400 for a level outside 0–3, 409 for one not yet open |
| `POST /api/campaign/:code/missions/:id/complete` | `{ stealth, badges?, results?, kills? }`: pays the contract once (a no-kill clause cuts it by `kills`, the hostiles killed but a target) and records its badges (`ghost`, `untouched`, `swift`, `bloodless`, `purge`); Ghost follows `stealth`, and an unknown badge is a 400. `results` (`caches`, `prisoners`, `tagged`, whole counts) pays the contract's rewards beyond credits; a field the contract's type does not report, or a count above what the contract holds, is a 400 |
| `POST /api/campaign/:code/upgrades/:type` | Buys `weapon`, `armor`, or an ability upgrade (`assault`, `support`, `recon`, `tech`) |
| `POST /api/campaign/:code/loadout` | `{ weapon, armor }`: how the gear levels are spent (`piercing`, `suppressed` or `extended`; `heavy` or `light`); free |
| `POST /api/campaign/:code/recruits/:id` | Hires an offered recruit |
| `DELETE /api/campaign/:code/roster/:id` | Dismisses an operative |

Each client IP gets 120 `/api` requests a minute, and 20 of them may create players. Past either limit the Worker answers 429 without reaching the Durable Object, so one client cannot use up the Durable Object's daily quota. Cloudflare counts these per location and only approximately, so they slow a flood down rather than cap it exactly. The Worker stops reading a request body past 16 KB and answers 413.

## Deploy

GitHub Actions deploys on every push to `main` (`.github/workflows/deploy-to-cloudflare.yml`) after the checks in `.github/workflows/verify-game-and-worker.yml`, which also run on pull requests.

1. Create a Cloudflare API token from the "Edit Cloudflare Workers" template.
2. In the repository settings, create a `production` environment and add the secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` to it. Add required reviewers there to gate deploys.
3. Push to `main`. The first deploy creates the `PlayerCampaign` Durable Object namespace from migration `v1`.

To deploy by hand, run `npx wrangler login`, then `npm run deploy`.
